something here rather than naming where it lives, put it in the target
document and shorten the line.

**`docs/port/PHILOSOPHY.md` is the one to read before changing behaviour.** It is a
register of 53 places the bash is loose *on purpose*, each with the ruling
behind it. Most of them look like defects. A port that "fixes" one has
reversed a decision.

**This repo is not governed by scrumux** — it builds it, and a tool that
writes records about its own construction bakes that afternoon's policy
into law (`RULINGS.md`, R-001). The CLI refuses its own governance verbs
here, keyed on the committed `.scrumux-ungoverned` marker at the root.
`RULINGS.md` is therefore the only governance record this repo has:
manifesto, then how a session here is governed, then every ruling. Nothing
is mirrored from a journal, because there is no journal.

## The oracles — the things that outlive bash

Three implementations are frozen so the port keeps being checkable after
`.deploy-claude/` loses its bash. Each records what bash DID, which is not the same
as what is right — for one of them the recorded answer is measurably wrong,
and that is the point.

| Oracle | What it pins | Where |
|---|---|---|
| the awk tokenizer | `walls_cmd_words`, byte-identical, plus 169 golden cases (130 harvested from the hook suites) and 10,000 generated cases per run | `test/oracle/cmd-words.awk.sh`, `test/oracle/oracle.test.ts` |
| `jq` | `jq .` output over every live journal | `test/unit/jqformat.test.ts` |
| `grep -E` | POSIX ERE semantics — **plural, because two greps on one machine disagree, and `[[:space:]]` changes with `LC_ALL`**. One dialect ratified: BSD-compatible, C-locale character classes (D-0090) | `test/unit/ere.test.ts`, `test/unit/walls-posix-classes.test.ts` |

## Running things

| Want to | Do |
|---|---|
| Run one suite | `sh tests/<name>-tests.sh` — prints `N passed, M failed`, exits non-zero on any failure |
| Run every suite | `npm run parity:suites` — all 41, against bash and against whatever the flip list owns |
| Run the TypeScript unit tests, coverage-gated | `npm test` (thresholds are CI-fatal; see `vitest.config.ts`) |
| Compare bash and TypeScript on the same case | `npm run diff` (tiers 1+2, the phase gate) · `npm run diff:all` (+ sandbox and corpus) |
| Prove the four walls, three ways | `npm run walls` — the hook suites through the `.sh` SHIMS; every payload (harvested AND seeded) through the `.mjs` DIRECTLY, in a deployed root and an undeployed one; and the fail-closed checks |
| Prove the built CLI end to end, as a process | `npm run smoke` — `tools/ci/smoke.mjs`: version, help, a refusal's exit code, `harness deploy` into a fresh git repo, `status session --json`, a journal write re-read for CR bytes, two wall bundles fed a hook payload on stdin. Needs `npm run build` first. No shell anywhere in it, which is the point |
| See which of these run on which OS, and why | `.github/workflows/ci.yml` — ubuntu and macOS take every gate; Windows takes typecheck, lint, build, the POSIX-free vitest partition and the smoke. `--impl ts` parity is opt-in from the Actions tab, not a gate |
| See what Windows can and cannot run | `npm run ci:partition` — `tools/ci/posix-partition.mjs` classifies every `test/**/*.test.ts` against signals read out of its own source and prints both buckets with the line that decided each. Never a hand-written list |
| Run the vitest suite the way Windows runs it | `npm run test:ts-only` — the eligible subset only, with the skipped count printed before and after. Simulate the platform locally by removing `sh`, `bash`, `jq`, `grep`, `awk` and `sed` from `PATH` |
| Rebuild the tokenizer's golden corpus from the hook suites | `npm run oracle:corpus` |
| Ask the frozen awk what a command tokenizes to | `printf %s '<cmd>' \| sh test/oracle/cmd-words.awk.sh` |
| See what a divergence actually looks like | `npm run diff -- --only <case-id> --show <case-id>` |
| Drive a realistic operator session end to end | `npm run sandbox` — a fresh mktemp widgetworks repo, deployed, ~90 invocations |
| Refresh the committed bash baseline | `npm run sandbox -- --write-baseline` → `test/baseline/sandbox-bash.json` |
| Regenerate the generated fixture tiers | `npm run sandbox` (tier: sandbox) · `npm run corpus` (tier 3, scrubbed) |
| Understand what the differential is allowed to forgive | `tools/differential/canon.mjs` — a named, unit-tested rule list |
| Move a verb from bash to TypeScript, or move it back with no redeploy | `.deploy-claude/scripts/lib/ts-owns.sh` header |
| See what a verb answers without changing anything | `scrumux <noun> <verb> --json` — exactly one JSON object on stdout |
| Read an exit code | 0 the assertion held · 1 it did not · 2 the command could not run. Advisories never move it |
| Check a repo is actually live, not just copied | `scrumux harness verify <path>` |

## Not built yet

These land as the port proceeds and get their line here when they exist,
not before. An index that names a file which is not there is worse than no
index.

The noun modules and the graphs used to be listed here. They are not
pending any more — Waves 3–5 seated every noun on the roster, Wave 5I
(`6eee937`) made the schema sweep native TypeScript and took Python off the
TS path, and Wave 5J (`a50e511`) put the code-graph builder in Node behind
`tools/grammars/`. Their lines moved up into *The TypeScript side*, which is
where a landed thing belongs. Every noun on the bash roster now has a
registry line in `src/nouns/registry.ts`, and `npm run diff` is what says so
out loud: it prints the UNPORTED cases by name with a count, so IT is the
check on whether this paragraph has gone stale again — never a tally written
down here, which is the drift this section was carrying before.

- **The install story** — `npm i -g`, then the single binary (Phase 6).
  As of this commit (2026-09-01) the `.deploy-claude/dist/` bundles are
  staged by hand and `.deploy-claude/hooks/*.sh` on disk is still bash.
  Whether `harness deploy` yet ships the bundles and lays the `.sh` hooks
  down as shims *in the deployed repo* is deliberately not asserted here:
  that seam is moving, and an index that guesses at it is the second copy
  D-0010 warns about. `.deploy-claude/scripts/lib/cmd-harness.sh` and
  `src/nouns/harness/` are what deploy actually does; read them, not this.
